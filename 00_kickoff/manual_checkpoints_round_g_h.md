## 1️⃣ T15.3 门禁结构签字（最优先）

**要你定什么**：是否把 `strategy_gate` 的判据从「全样本命中率 ≥52%」改为
「**置信度 ≥thr 子集命中率 ≥52% 且 覆盖率 ≥5%**」双指标（thr ∈ [0.2, 0.3]）。

**证据**
- 保留期（独立、未参与任何扫描）读数：阈值↑→命中率↑**单调**，三周期无一处反转；
  thr=0.2 → 52.9%~55.6%（覆盖 17%~36%）；thr=0.3 → 55.2%~58.5%（覆盖 5.6%~14.4%）；
- 20d @ 0.3 证据最强（58.48% / 14.4%）；5d @ 0.3 覆盖 5.6% 贴 5% 下限，**最脆弱**；
- 决策单五种状态已实测：无候选 → `reject`；未挑阈值/无签字 → `defer/pending`；
  **唯一通关 = 候选阈值 + 人工签字**。
- 反向证据（必须一并看）：全样本口径三周期命中率仍 <52%；S17 CPCV 收缩后
  IC 为正但 PBO 未扫；保留期水位整体高于 walk-forward 属**时段效应**，不得择优引用。

**现状默认**：`mode: report_only`、`freeze_structure: true`，`strategy_gate` 逐字段零变更。

**签 / 不签的后果**

- **签**：`approve` 批准的只是**证据**——我仍需另开 PR 逐字段 diff 给你审，才能真改配置。

## 2️⃣ T16.4 区间口径取舍

**要你定什么**：置信分的刻度用哪种——
- **A 保形区间口径**：粒度只有 `{0, 0.5}` 两档，能表达「排除了一个方向」，表达不了**程度**；
- **B 概率距离口径（现行 `|p−0.5|×2`）**：连续可分辨，高阈值端更有分辨率
  （thr=0.5 时 命中 60.25% / IC 0.3348 / 覆盖 44.4%，区间口径 58.21% / 0.2501 / 68.3%）。

**证据**：对照判定 **`mixed`**（不构成改善结论）；覆盖率 0.8 档实测 0.7978（临界
`anti_conservative`）、0.9 档 0.9189（`on_target`）；原始概率 **ECE 0.0904** ——
「模型说的概率」不能直接当概率用（这是 S19/H4 的输入）。

**现状默认**：`model.factors.conformal.enabled=false`，区间口径不进生产链路。

**建议口径（供参考，不代做）**：**B 作生产刻度、A 作覆盖率审计与风控旁证** ——
两者不是「谁更好」，是「要不要连续刻度」。若坚持单一口径，A 需要先解决粒度问题。

`plan.json` 里被误标 `completed`**（结论已交付，但「是否采纳」这一人工动作并未发生）：

| 检查点 | 原文 | 修正后 | 说明 |

**为什么必须改**：这两项若留在 `completed`，`schedule/plan.json` 就会对外
宣称「已决策」，而实际没有任何人签字 —— 正是本轮纪律要防的事。

新增守卫测试 `tests/test_roadmap_manual_checkpoints.py` 钉死：
人工检查点只允许 `pending` / `confirmed`、**不得标 `completed`**、
不得进 `auto_acceptable`、决策包与排期**双向一致**。

**2026-09-12 追加**：上述偏差经用户确认后由 `pending` → `confirmed`
（确认对象 = 当时给出的现状默认值），`completed_at` 一律不再出现。
守卫同步升级为「签字校验」：`confirmed` 条目必须有
`confirmed_by` / `confirmed_at` / `decision` / `scope` / `out_of_scope` / 证据引用，
缺一即失败 —— **没有签字依据的 `confirmed`，与没有依据的 `completed` 一样是假进度**。
