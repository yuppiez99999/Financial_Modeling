# Laya 只读接入的准入边界（Issue #66 · J 轮 S26）

**当前真相**：S26 把 Laya（Convai 开放权重、Jev 同构）定为**只读第二决策源**，
并**只留 Laya**（Jev 闭源在线臂按用户决策移除）。本文件记录这条接入链路的
**纪律边界**与**接入前必须过的可复现性证明**，不记录"Laya 是否有用"
（那须 T26.1 批依赖 + 真实权重后才有读数）。

可复算命令（全部只读、CI 离线）：

```bash
python main.py laya-decision     # 适配器 + 离线对照 + 级联冒烟 + 决策单（T26.2~T26.4）
python main.py laya-replay       # 接入前冻结快照回放对账（T26.6）
```

只读：`affects_gate=false`、`affects_signal=false`（结构性保证，非口头约定）；
`strategy_gate` 逐字段零改动。

## 一、边界（写在最前）

1. **不进信号路径**：全部产出无 `probability` / `direction` / `signal` 字段，
   `readonly=True` 硬编码，只能挂报告层（`attach_laya_note`）；
2. **CI 离线**：只用本地权重；权重缺失即如实降级 `unavailable`，**不联网、不下载、不报错**；
3. **不编造效果**：真实权重未接入 ⇒ 对照记 `unverifiable` + **止损**（延续 H5 先例）；
4. **不代签**：T26.1（重型依赖准入）/ T26.5（保留决策）是人工检查点，
   无 `decided_by` 时结论最多 `defer` / `cancel`。

## 二、T26.6：为什么「回放对账」必须排在 T26.1 之前

T26.1 是「是否接受 ~1.7GB fp32 / ~2GB RAM 的**重型依赖**」。这里有一个**顺序风险**：

> 要是依赖先批了，而 T26.3 的离线对照其实**不可复现**，那 1.7GB 就被**白批**。

这不是"数据会变"这种含糊担忧，而是两条**实测可查**的结构事实：

| 事实 | 实测（`600519.SH`） |
|---|---|
| 对照用的 `data/raw/<symbol>.csv` 是**滑动增量缓存** | 只保留最近 **400** 行，窗口随每次追加滑动 |
| 它**按日期标签对齐，而标签是错位的** | 同一价格序列，缓存日期比冻结快照整体晚 **5 个交易日** |

⇒ 同一份模型输出，在"采集日 A"与"采集日 B"上做对照，**样本落在不同的价格序列上** ——
读数变了却查不出原因。本项目在 Issue #55 已经吃过同款亏（各轮读数被拆在不同子集上，
事后专门做一轮「统一切片 + 冻结」才敢写结论）。

`python main.py laya-replay` 把这件事从**事后补救**提前成**接入前的准入条件**。

## 三、判据（写死，防事后找补）

1. **按位置比，不按日期 join**：缓存日期标签本身是错的，按日期合并会把"标签错位"
   误报成"数据不一致"，掩盖真正的结论；按位置逐行比金额列，才能同时回答
   「是不是同一价格序列」与「标签有没有错位」两件事；
2. **日期标签逐值核**，不是只比区间 —— 区间相同而内部错位是**最隐蔽**的一种；
3. **行数即窗口**：`rows_frozen >= rows_cache`，否则快照被截断，回放窗口 ≠ 生产窗口；
4. **只读**：不写数据、不改配置、不联网；
5. **不把"没证明"写成"证明"**：缺缓存 / 缺快照 / 重叠行数 < 100 ⇒ 如实 `unverifiable`。

结论词表（fail-close）：

| 结论 | 含义 | 对 T26.1 的含义 |
|---|---|---|
| `replayable` | 价格逐行相等 + 标签对齐 | 可批：对照能离线复算 |
| `replayable_with_label_drift` | 价格逐行相等，**仅标签错位** | 可批，但口径**必须认冻结快照的日期** |
| `snapshot_diverged` | 不是同一价格序列（或快照被截断） | **先修数据链再批依赖** |
| `unverifiable` | 成对标的不足 | 材料不足，不给结论 |

## 四、主读数（真实数据，2026-09-24，只读）

| 项 | 值 |
|---|---|
| 成对标的（缓存 ↔ 冻结快照） | **3 / 28**（其余 25 只缓存窗口已滑走，快照仍在） |
| 价格序列逐行相等 | ✅ **3/3**（`600519.SH` / `000858.SZ` / `300308.SZ`） |
| 日期标签对齐 | ❌ 0/3（错位 **5~7 个交易日**） |
| 结论 | **`replayable_with_label_drift`** |

**读法**：对照**可离线复算**（价格同一份），但**口径必须以冻结快照的日期为准**；
混用缓存的错位标签会让日期语义与 `reports/*.frozen.*.json` 里的读数**对不上** ——
这正是 Issue #55 第九轮把读数冻结入库要防的那类错位。

## 五、踩坑与解法（contains）

- **contains 增量缓存 ≠ 快照**：`data/raw/*.csv` 是"最近 N 行"的滑动窗口，
  且日期标签与真实交易日错位。任何**跨天复现**的对照都不能直接建在它上面；
  要么认冻结快照，要么在报告里显式记下"本次读数绑定的数据切片"。
- **contains 只比日期区间不够**：两段区间可以完全相同而内部逐行错位，
  只比 `[min, max]` 会漏掉这类错位。必须**逐值**核。
- **contains 顺序风险要写进排期**：把"可复现性"列为**先于**"依赖准入"的自动任务
  （T26.6 先于 T26.1），比事后写一句"注意复现"有用得多 —— 后者没人会执行。
